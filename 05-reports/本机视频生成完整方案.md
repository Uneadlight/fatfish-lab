## 1. 总体路线：三阶段递进

```
阶段一  LTX-Video 2B   →  跑通流程、调好参数（6GB，快，最快见到成品）
阶段二  Wan2.2 5B      →  拉到最高质量（17.8GB，慢，VBench 同组第一）
阶段三  Real-ESRGAN    →  超分补细节（64MB，可选）
```

**为什么是这个顺序**：LTX 小、快、参数少，先用它把「下载→放目录→装→跑→出片→合成」整条链路打通；万一 8GB 根本跑不动视频，只浪费 6GB 而不是 18GB。跑通之后再上 Wan 冲质量。

## 2. 阶段一：LTX-Video 2B（跑通）

### 2.1 下载清单

| 文件 | 目标路径 | 预估大小 | 来源 |
|---|---|---|---|
| `ltx-video-2b-v0.9.5.safetensors` | `ComfyUI/models/diffusion_models/` | ~5.5 GB | `Lightricks/LTX-Video`（HF） |
| `ltx-video-2b-v0.9.5-vae.safetensors` | `ComfyUI/models/vae/` | ~300 MB | 同上 |
| `t5xxl_fp8_e4m3fn_scaled.safetensors` | `ComfyUI/models/text_encoders/` | ~4.9 GB | `Comfy-Org/.../split_files/text_encoders/` |

**合计约 10.7 GB**。

**下载方式**（三选一，按可用性排序）：
1. `hf-mirror.com` 镜像（HF 加速，国内通常可用）
2. `modelscope.cn`（阿里，国内最快）
3. 官方 `huggingface.co`（可能超时）

**命令模板**（用 curl 断点续传）：
```bash
curl.exe -L -C - -o "models/diffusion_models/ltx-video-2b-v0.9.5.safetensors" \
  "https://hf-mirror.com/Lightricks/LTX-Video/resolve/main/ltx-video-2b-v0.9.5.safetensors"
```

### 2.2 安装（不需要装节点）

LTX-Video 是 **ComfyUI 原生支持**的（0.45.0 已内置工作流模板）：放好文件 → 重启 → 菜单「工作流 → 浏览模板 → Video → LTX-Video」。

### 2.3 首次试跑（最保守参数）

| 参数 | 值 | 理由 |
|---|---|---|
| 分辨率 | **512 × 512** | 最小可行，先确认不 OOM |
| 帧数 | **33 帧**（约 1.4 秒 @24fps） | 视频越长显存越吃 |
| 步数 | **8 步**（LTX 蒸馏模型） | 官方推荐，快 |
| CFG | 3.0 | LTX 官方参数 |
| 种子 | 固定 42 | 便于对比 |

**预期耗时**：约 20–60 秒（RTX 4060 8GB，LTX 官方说 4060 能 720x480x121 帧 <1 分钟，我们先用 512 保守）。

### 2.4 验收标准（全过才算跑通）

1. ✅ 输出 MP4/GIF 文件存在且 > 100KB
2. ✅ 时长 ≥ 1 秒
3. ✅ 画面不是纯噪声/纯色
4. ✅ 显存峰值 < 8GB（记录 `nvidia-smi` 最大值）
5. ✅ 连续跑 3 次不崩

### 2.5 跑通后立刻做的三件事

1. **记录基线**：把参数、耗时、显存写进 `知识库/03-实测/`
2. **升分辨率**：512 → 768 → 1024，找到不 OOM 的最大值
3. **评估质量**：出一支 3 秒视频，自己先看；满意再进阶段二，不满意先调参数

## 3. 阶段二：Wan2.2 TI2V-5B（冲质量）

### 3.1 下载清单

| 文件 | 目标路径 | 预估大小 |
|---|---|---|
| `wan2.2_ti2v_5B_fp16.safetensors` | `ComfyUI/models/diffusion_models/` | ~10 GB |
| `wan2.2_vae.safetensors` | `ComfyUI/models/vae/` | ~1.4 GB |
| `umt5_xxl_fp8_e4m3fn_scaled.safetensors` | `ComfyUI/models/text_encoders/` | ~6.7 GB |

**合计约 18.1 GB**。来源：`Comfy-Org/Wan_2.2_ComfyUI_Repackaged`（官方重打包，工作流现成）。

### 3.2 装（同样不需要节点）

Wan2.2 也是 ComfyUI 原生支持：菜单「工作流 → 浏览模板 → Video → Wan2.2」。

### 3.3 首次试跑

| 参数 | 值 |
|---|---|
| 分辨率 | **512 × 512** |
| 帧数 | **33 帧** |
| 步数 | **20 步**（Wan 官方推荐） |
| CFG | 5.0 |
| 耗时预期 | **5–15 分钟**（比 LTX 慢很多，这是正常的） |

### 3.4 如果 OOM（很可能）

按顺序降级：

1. **换 GGUF Q4 量化**：`QuantStack/Wan2.2-TI2V-5B-GGUF` 的 `Q4_K_M`（约 4GB）+ 装 `ComfyUI-GGUF` 节点
2. **降分辨率**：512 → 384
3. **降帧数**：33 → 17
4. **开 tiled VAE**：ComfyUI 的 VAE Decode 节点选 `tiled`

## 4. 阶段三：超分链路（可选，出片前最后一步）

### 4.1 下载

| 文件 | 大小 | 路径 |
|---|---|---|
| `RealESRGAN_x4plus.pth` | 64 MB | `ComfyUI/models/upscale_models/` |

### 4.2 两种做法

**做法 A：ComfyUI 里逐帧超分再合成**（质量好，慢）
```
视频拆帧 → 每帧 Image Upscale (RealESRGAN x4) → VHS Video Combine
```

**做法 B：剪映「增强质量」**（最快，够用）
拖进剪映 → 视频 → 基本 → 增强质量 → 选「超清」→ 导出。

### 4.3 超分的三个限制（别抱太大期望）

1. **帧间闪烁**：逐帧超分会让画面抖（每帧独立算细节）
2. **伪影放大**：原片的变形/糊会被放大 4 倍
3. **不能创造细节**：480p → 4K 只是像素多，不是细节真

## 5. 参数调优矩阵（跑通后按此表试）

| 维度 | 低 | 中 | 高 | 影响 |
|---|---|---|---|---|
| 分辨率 | 512 | 768 | 1024 | 显存 ↑↑、质量 ↑ |
| 帧数 | 17 | 33 | 49+ | 显存 ↑、时长 ↑ |
| 步数 | 8 | 20 | 30 | 耗时 ↑、质量 ↑ |
| CFG | 3.0 | 5.0 | 7.0 | 贴合提示词 ↑、可能过饱和 |
| 种子 | 固定 | 固定 | 多试 | 决定构图 |

**每次只改一个参数**，记录耗时/显存/主观质量（1-5 分）。

## 6. 故障处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `CUDA out of memory` | 显存不够 | 降分辨率/帧数，或换 GGUF |
| 生成很慢（>30 分钟） | 模型太大 | 确认没用 CPU 跑；看 `nvidia-smi` 是否真在用 GPU |
| 画面全黑/纯噪 | 步数太少或 CFG 错 | 步数升到 20+，CFG 5.0 |
| ComfyUI 起不来 | 模型文件损坏 | 校验文件大小与来源 |
| 内存爆掉（15.2GB 不够） | 模型 + VAE 同时加载 | 关浏览器、关 DSH 之外的程序 |

## 8. 我的判断（先说清楚）

1. **8GB 跑 5B 模型有风险**：FP16 版 10GB 模型理论上超显存，公司云厂商教程都要求「FP8/GGUF + 分级卸载」，所以阶段二很可能要退到 GGUF
2. **LTX 是稳妥的起点**：6GB 内、官方实测 4060 8GB 可行
3. **质量天花板不高**：8GB 的模型只能出 480-720p 质量，别期待 1080p 电影感
4. **超分是补救**：想让画面「看起来高级」，剪映的增强质量性价比最高
