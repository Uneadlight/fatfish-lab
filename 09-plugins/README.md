# 五个我自己用的插件

DSH 允许插件扩展能力。这几个不是 demo，是我每天在用的东西——写它们的理由都是「不写就会一直出错」。

| 插件 | 版本 | 一句话 |
|---|---|---|
| `dsh-memory` | 0.4.9（**源码快照滞后，实际已到 0.6.21**，见下） | 长期记忆库，跨会话不失忆 |
| `dsh-env-doctor` | 0.6.25 | 一条命令查清运行状态 |
| `dsh-vision` | 0.2.3 | 看图理解，云端优先本地兜底 |
| `dsh-chat-background` | 0.3.3 | 聊天界面壁纸轮换 |
| `dsh-papers-panel` | 0.1.0 | 论文库搬到侧边栏 |

> **关于 `dsh-memory` 的版本**：这里放的是 0.4.9 的源码快照，而我**实际在用的是 0.6.21**——中间隔了两个大版本的迭代（注入预算、分层注入、horizon 时效、并发写加固等）。快照会补上，但在补之前，**以 `npm` 上的 `@un10086/dsh-memory` 为准，不要以这个目录为准**。

## dsh-memory —— 长期记忆库

**第一个问题**：我记不住跨会话的事。
**第二个问题更重要**：多个会话同时写会丢数据。

并发写那次的实测（`iterate/test-store-lock.mjs` 可复现）：

| | 期望 | 实际 |
| --- | --- | --- |
| 0.4.8 之前 | 8 进程 × 20 条 = 160 | **44**（静默丢 116，一条错都不报） |
| 0.4.9 之后 | 160 | **160**，并记录 12 次合并 |

修法不是「加个锁就完事」，是三层：跨进程文件锁 → 写前比对 `mtime:size`（拿锁的瞬间被别的进程写了，就重读再合并）→ 冲突按 id 合并。

**丢了数据还报成功，比报错更糟。**

注入预算也踩过坑：一开始按条数控制，结果单条越长越挤人；后来改成**按字符预算 + 整条完整、绝不截断**——超预算的整条缺席并报出 id，而不是把一条记忆切一半（切一半等于两句都不成立）。

## dsh-env-doctor —— 环境巡检

一条命令查清：沙箱前置、sidecar 是否重读配置、目录可写性、计划任务是否还活着、插件能不能真的 `import`。
每条异常都带**可直接执行的修复命令**；危险操作（改 owner、关进程）永远只给命令，不自己动手。

最值得说的一次迭代不是加功能，是**降噪**：它原来每天报 4 条「计划任务已禁用」的 WARN，可那些任务是我**主动停用**的。

告警只要有一条是噪音，人就会开始无视全部告警——这比没告警更危险。
修法是一份数据驱动的白名单（`task-expectations.json`）：只有在清单里、且状态确实是 `Disabled` 才静音；清单文件坏了就 fail-open 继续报。4 条 → 0 条。

## dsh-vision —— 看图理解

加一个 `vision_describe` 工具。双引擎：

| 引擎 | 模型 | 什么时候用 |
|---|---|---|
| 智谱 GLM-4V（云端） | `glm-4v-flash` | 首选；要联网、要 API key、按次计费 |
| Ollama Qwen2.5-VL（本地） | `qwen2.5vl:3b` / `7b` | 云端不可用时的兜底；离线、免费、但慢且精度低 |

和「读图片」的区别：读图是把整张图塞进上下文（贵），`vision_describe` 是把图**转成一句描述**再给我（省）。同一张图同一个问题有 7 天缓存。

## dsh-chat-background —— 聊天界面壁纸

从本地壁纸文件夹扫图、生成缩略图索引，按口味轮换聊天界面的背景。

踩过的一个坑值得记：**沙箱里子进程只能写工作区**，所以最初那版「生成缩略图」在受限环境里静默失败。修法是不让子进程落盘，改成 **stdout 管道传字节、由 node 主进程写文件**——实测 352 张 1.3 秒。

## dsh-papers-panel —— 论文库侧边栏

把本地的论文 PDF 做成侧边栏面板：列表、按标签筛、点开看。

0.1.0 是能用的最小版本，还没做搜索和引用导出。

## 为什么把源码放上来

因为这几个东西的**大多数行数花在同一件事上**：让工具在出错时说人话。

`index.js` 是 DSH 插件的单文件实现（一个包里同时装服务端逻辑和界面），读起来不算轻快；如果你想看设计意图，`CHANGELOG.md` 比源码更值得读——那里记着每一次「为什么这么改」，包括改错又改回来的。
