# 数据腐化审计

## audit_ssot.py

纯标准库，一个脚本回答一个问题：**文档里写的、代码里实现的、磁盘上躺着的，三处还对得上吗？**

8 个维度：参数漂移 / 知识库索引 / 依赖声明 / 死链 / 死代码 / 残留文件 / 僵尸目录 / 版本号。

第一次跑出 30 项，最后归零。归零的过程比那个数字有意思：

- **真错改了**：两处文档数字与代码不符、一个从没被引用的异常类、12 个第三方库没写进 `requirements.txt`、缺 `__init__.py`
- **误报改规则**：路径含空格被截断、历史文档里的旧路径、`.tmp` 目录
- **最值钱的一条**：`requirements.txt` 写 `Pillow`，代码里 `import PIL` —— **import 名 ≠ 分发名**。给审计加了约 20 组别名表（`bs4→beautifulsoup4`、`cv2→opencv_python`、`win32api→pywin32`…）
- **不改的**：一个「图标路径含中文导致白屏」的历史结论，查了半天也没能证实那个根因——所以写成「未证实」，而不是删掉或当成结论

最后一条是重点：**审计的作用是找出不一致，不是把数字按到 0。** 为了让报表好看而删掉一条自己解释不了的告警，就是把审计变成装饰品。

## global-healthcheck.py

四维度体检：git 工作区一致性 / 数据完整性 / 计划任务 / 磁盘。

这东西的价值不在「查得多」，在**查完之后我敢不敢说一句『今天没问题』**。
