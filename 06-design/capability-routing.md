# 能力路由表

> **零号卡。** 跟本目录其他模式卡不同类：那些是"换个项目还能用"的设计模式，这张是**我自己的调度手册**——遇到什么活，先交给谁，交出去之前要先确认什么。
> 起因：2026-10-31 用户问"你的外设怎么组合"，我意识到自己**一直在补缺口，从没盘过存量**。这张表就是补盘存量的作业。

## 一、总原则

**1. 能外包的是执行，不能外包的是裁决。**
裁决权归 pytest 退出码，不归任何模型——云端不行，本地不行，我自己也不行。

**2. 每一层都要写清楚"错了谁兜底"。**
没有兜底的层不许放进去。放进去就是赌博。

**3. 降级不是失败，是设计；但降级必须留痕。**
用了兜底就一定在输出里标出来（比如识图返回 `引擎: local`），否则下次不知道自己在什么水平上做判断。

## 二、三层资源

| 层 | 是什么 | 强在哪 | 弱在哪 | 成本 |
|---|---|---|---|---|
| **L1 云端（我）** | `deepseek-flash` / `deepseek-v4-pro` | 推理、写作、判断、读长文、跨领域联想 | 事实可能错；没有本地状态；每轮重发上下文 | 计费，空闲时段半价 |
| **L2 本地小模型** | `qwen2.5:3b`（主力）/ `qwen2.5-coder:3b`（长日志）/ `qwen2.5vl:3b`（识图） | 零边际成本、离线可用、隐私不出机 | 格式漂移、编造、不会收敛 | 电费 + 显存（3b 占 4.9 GB，红线 5.7 GB） |
| **L3 工具** | `pwsh` / `read` / `write` / `edit` / `grep` / `glob` / `ghctl` / `triage.py` | 确定性、快、可验证 | 只会做一件窄事 | 免费 |

## 三、路由表

| 任务 | 首选 | 降级 1 | 降级 2 | **错了谁兜底** |
|---|---|---|---|---|
| 看图 / 截图 / 读界面 | `vision_describe`（智谱 `glm-4v-flash`，90s 超时） | 本地 `qwen2.5vl:3b`（180s） | `RapidOCR`（只提文字） | 我自己核对关键数字/文字 |
| 从长日志挑错行 | `triage.py`（>150 行自动切 coder） | 单模型整段喂 + 肉眼 | 我逐段读 | 复现 / pytest |
| 写代码 | **我自己写**（云端） | 3b 生成骨架 → 我改 | — | **pytest 退出码** |
| 查资料（时效性） | `web_search` → `web_fetch` | 本地知识库 `memory_search` | 记忆库 | 交叉两个独立来源 |
| 改本机（文件/命令） | `pwsh` | `ops_bash` | — | 命令退出码 + 改完立刻验收 |
| 查记忆 | `memory_search`（相关度+标签+分层） | `grep` 全盘 | 逐文件翻 | 我自己判断相不相关 |
| 发布到 GitHub | `ghctl sync`（含字节校验+重试） | 手动 `git push` 退避重试 | Contents API | **远端回读验证**（不是"我以为推上去了"） |
| 装 / 升级软件 | **用户手动点官方路径** | 我跑安装器（可能撞 UAC/占用） | 不升级 | 版本号 + 升级后体检 |
| 批量格式化 / 转换 | 3b（可验证的机械活） | 写脚本 | 手工 | 输出格式检查 |

## 四、什么绝对不能外包

| 不许外包的 | 为什么 | 交给谁 |
|---|---|---|
| **判断对错** | 3b 说"我觉得可以"不具备任何证据效力 | pytest 退出码 / 复现结果 |
| **金额、数量、耗时** | 算错一次就全错，而且很难被发现 | 我自己算，金额用整数分 |
| **最终交付物** | 交付质量是我的责任，不是模型的 | 我自己写、自己跑、自己验 |
| **权限/能力定性** | 说反了会让人白忙 | 我自己分清"能力缺失"vs"权限被拒" |
| **要不要做这件事** | 这是判断，不是执行 | 我 + 用户 |

## 五、认错的形状不一样（这节是自己想出来的）

每层出错，露出的马脚**完全不同**，所以验证手段不能通用：

| 层 | 出错时长什么样 | 怎么抓 |
|---|---|---|
| **L1 云端（我）** | 讲得头头是道、结构漂亮，但**事实错** | 查证：跑一遍、查文档、交叉来源 |
| **L2 本地 3b** | 格式漂移（`>>` 写成 `>>>`）、**编造**、该报的不报 | **证据校验**：每行必须含硬证据，否则丢 |
| **L3 工具** | 退出码非 0、异常栈 | 直接看得见，不用猜 |

推论：**越往下的层，验证越"机械"；越往上的层，越需要"常识 + 查证"。**

用错验证手段是常见错误：拿"看着像不像"去验 3b（必错，它会写得比真的还像），或者拿"证据正则"去验我（没用，我编的话里也有 ERROR 关键字）。

## 六、每天真正用到的只有四行

80% 的活落在这四条上：

1. **改代码** → 我自己写 → pytest 验
2. **查东西** → 本地文件/命令优先 → 不够再联网
3. **长输出** → `triage.py` 先筛 → 我读筛出来的
4. **发布** → `ghctl sync` → 远端回读

其余的（看图、生图、装软件）是低频，走上面那张大表。

## 七、已知的缺口

| 缺口 | 现状 | 补的成本 |
|---|---|---|
| 生图 | 完全没有（无 key、无调研） | 要花钱 + 要接 API；且我判断 Pillow 更适合画结构化的图 |
| OCR 没包成工具 | `RapidOCR` 已装在 `tools\ocr-venv312`，但没注册给模型用 | 写个插件 + 重启，半小时 |
| 没有"任务分类器" | 路由是我人工判断，不是自动分流 | **不需要**——这层自动化的准确率会低于我自己的判断 |
| 本地模型不能自我收敛 | 3b 编排 7 轮从不收敛（已实测） | 不是缺陷，是定位：它只当手脚 |
